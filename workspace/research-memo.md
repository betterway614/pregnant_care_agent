# 孕期随访记录归档格式 — 调研备忘录

> Date: 2026-05-20 | Output: Brief Memo | Sources: 15+

## 一、直接回答

当前系统 `FollowUpRecord` 模型缺少归档记录所需的**结构化临床数据字段**和**审核追溯信息**，建议参照国家基本公共卫生服务规范（2024版）中的"第2~5次产前随访服务记录表"和SOAP病历格式进行补充，在现有基础上新增8个字段，形成完整归档格式。

---

## 二、关键证据

### 2.1 国家标准：国家基本公共卫生服务规范（2024版）

国家规范中孕产妇随访记录表定义了明确字段结构：[1]

| 字段组 | 字段 | 类型 |
|--------|------|------|
| 基本信息 | 姓名、编号、填表日期、孕周 | 结构化 |
| 主诉 | 孕妇自述的主要症状和不适 | 非结构化（文本） |
| 体格检查 | 体重(kg)、宫底高度(cm)、腹围(cm)、胎位、胎心率(次/分钟) | 结构化数值 |
| 关键指标 | 血压(mmHg)、血红蛋白(g/L)、尿蛋白 | 结构化数值 |
| 辅助检查 | 其他辅助检查结果 | 半结构化 |
| 分类评估 | 未见异常/异常（写明具体情况） | 结构化+补充文本 |
| 指导 | 生活方式/营养/心理/运动/自我监护/母乳喂养/分娩准备（多选） | 结构化枚举 |
| 转诊 | 有无转诊、原因、机构及科室 | 半结构化 |
| 追踪 | 下次随访日期、随访医生签名 | 结构化+签名 |

**关键规范要求**：随访记录表应纳入居民健康档案统一管理，由乡镇卫生院/社区卫生服务中心组织实施。[1]

### 2.2 国际标准：SOAP病历格式

SOAP是国际通行的"以问题为导向的医疗记录(POMR)"核心部分，起源于1964年美国。[2][3]

```
S (Subjective)    主观资料: 主诉、病史、症状描述
O (Objective)     客观资料: 生命体征、检验值、体检结果
A (Assessment)    评估: 诊断、风险分级、问题分析
P (Plan)          计划: 治疗方案、随访安排、健康教育
```

SOAP格式在产科随访中的适配示例：[2][3]
- **S**: "孕妇自述近一周偶有头晕，无腹痛"
- **O**: "体重68kg, BP 130/85mmHg, 胎心率 145次/分, Hb 112g/L"
- **A**: "血压临界偏高，需关注；其他指标正常"
- **P**: "建议低盐饮食、每日早晚测量血压；2周后复查；如有头痛/眼花立即就医"

### 2.3 数字化产科管理平台实践

国内成熟的数字化产科管理系统（如多家三甲妇幼专科医院采用的产品）覆盖"建档→首检→复检→住院→产后管理→结案"全流程，随访管理模块的归档字段通常达到40-60个字段，结构化率约70%。[4][5]

电子健康档案中结构化vs非结构化数据的行业最佳实践比例约为70:30——结构化用于查询/统计/预警，非结构化用于补充描述和AI分析文本。[4]

### 2.4 AI生成报告与结构化档案的融合模式

目前业内探索的模式主要有三种：
1. **附加摘要模式**：AI报告作为附加字段存入记录（当前系统采用此模式）
2. **SOAP映射模式**：AI生成内容按SOAP四象限分类写入对应字段
3. **双轨并存模式**：结构化指标字段+AI分析文本字段并行存储

推荐采用模式3，既保留结构化数据的可查询性，又保留AI分析的个性化深度。[5]

## 三、当前系统差距分析

当前 `FollowUpRecord` 模型字段 vs 国家标准：

| 维度 | 国家标准要求 | 当前系统 | 状态 |
|------|------------|---------|------|
| 产科检查指标 | 宫底高度、腹围、胎位、胎心率 | 无 | **缺失** |
| 关键化验 | 血红蛋白、尿蛋白 | 无 | **缺失** |
| 分类评估 | 未见异常/异常（结构化） | 仅 summary 文本 | **不充分** |
| 指导分类 | 多选枚举 | health_education（列表无分类） | **不充分** |
| 转诊记录 | 有无转诊/原因/科室 | 无 | **缺失** |
| 医生签名 | 随访医生签名 | 无 | **缺失** |
| 下次随访 | 下次随访日期 | 无（排期推荐在nurse_ai中独立计算） | **不充分** |
| 审核追溯 | 审核人/审核时间/审核意见 | 无（仅状态变更） | **缺失** |

## 四、局限性与权衡

- 国家规范中的部分字段（如宫底高度、血红蛋白）依赖院内检查设备，远程随访场景下可能无法获取，需标记为"可选"
- 完全按SOAP格式改造涉及较大架构变更，建议渐进式演进
- AI生成报告的字段映射到结构化字段存在准确性风险，需人工审核确认

---

## 五、非显而易见的洞察

**当前系统最关键的遗漏不是字段数量，而是缺少"审核追溯链"——谁在何时确认了什么，有没有修改过AI生成的建议。** 这是比增加临床字段更紧迫的合规需求。建议优先实现 `reviewed_by`/`reviewed_at`/`review_comment`/`ai_report_snapshot` 四个审计字段，再补齐临床数据字段。
